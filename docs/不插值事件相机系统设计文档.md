## 1. 系统概述

### 1.1 设计目标

构建一个**不插值**的事件相机视频通讯系统，核心特征：

- ✅ **无插值**: 接收端直接根据事件更新像素，不生成中间帧
- ✅ **事件驱动**: 仅传输亮度变化的像素（DVS事件）
- ✅ **对数空间**: 符合人眼感知特性，检测与重建数学一致
- ✅ **AER兼容**: 支持标准地址事件表示接口
- ✅ **端到端**: 从光输入到总线输出的完整链路

### 1.2 系统特点

| 特性        | 说明                    |
| --------- | --------------------- |
| **低延迟**   | 事件产生即传输，无需等待插值计算      |
| **高压缩**   | 仅传输变化像素，带宽节省 vs H.264 |
| **简单性**   | 无复杂插值算法，易于硬件实现        |
| **实时性**   | 向量化重建 < 1ms           |
| **数学一致性** | 检测端log，重建端exp         |

## 3. 核心模块详解

### 3.1 事件检测器 (EventDetector) - 含不应期

**文件**: `evs/event_detector.py`

**功能**: 检测像素级亮度变化，生成DVS事件，支持不应期

**关键参数**:

```python
EventDetector(
    threshold=20.0,              # 对数空间阈值
    min_area=10,                 # 最小区域面积
    use_adaptive_threshold=False, # 固定阈值
    blur_kernel=1,               # 无模糊
    use_log_space=True,          # 对数空间
    is_dvs_mode=True,            # DVS模式
    compare_with_previous=True,  # 与前一帧比较
    refractory_period=0.005      # 不应期（新增！）
)
```

**事件产生规则**:

```
ON事件:  log(I[t]) > log(I[t-1]) + threshold/255  且 超过不应期
OFF事件: log(I[t]) < log(I[t-1]) - threshold/255  且 超过不应期
```

**不应期实现**:

```python
# 不应期跟踪矩阵
self.last_event_time = np.zeros((height, width), dtype=np.float64)

# 检测时应用约束
time_since_last = current_time - self.last_event_time
time_mask = time_since_last > self.refractory_period
on_mask = (diff > threshold) & time_mask
```

### 3.2 事件编码器 (EventEncoder)

**文件**: `evs/event_encoder.py`

**功能**: 将事件编码为二进制格式，支持DVS和AER

**编码格式**:

```
关键帧包:
[帧序号(4)] [类型标志(4)] [时间戳(4)] [I帧长度(4)] [I帧数据]

事件帧包:
[帧序号(4)] [类型标志(4)] [时间戳(4)] [区域数(4)] [DVS事件数(4)] [AER字节数(4)]
[DVS事件列表] [AER数据]
```

### 3.3 事件解码器/重建器 (EventFrameReconstructor) - 向量化

**文件**: `evs/event_decoder.py`

**功能**: 解码事件并重建帧（不插值！向量化！）

**三种重建模式**:

| 模式             | 原理          | 适用场景   |
| -------------- | ----------- | ------ |
| `simple`       | 向量化加减固定值    | 快速预览   |
| `log_space`    | 向量化对数空间精确重建 | **推荐** |
| `accumulation` | 累积事件效应      | 长序列    |

**向量化对数空间重建**:

```python
# 1. 提取事件坐标和极性（向量化）
coords = np.array([[e.y, e.x, 1 if e.type == 'on' else -1] 
                  for e in events])

# 2. 转换到对数空间
gray = cv2.cvtColor(prev_frame, cv2.COLOR_BGR2GRAY).astype(np.float32)
log_I = np.log(gray + 1.0)

# 3. 向量化累加事件（O(1)批量操作！）
y_idx = coords[:, 0]
x_idx = coords[:, 1]
polarities = coords[:, 2]
delta = polarities * (threshold / 255.0)
np.add.at(log_I, (y_idx, x_idx), delta)

# 4. 指数映射回线性空间（数学一致性！）
I_new = np.exp(log_I) - 1.0
I_new_clipped = np.clip(I_new, 0, 255).astype(np.uint8)
```

### 3.4 AER总线接口 (AERBusInterface)

**文件**: `evs/aer_bus.py`

**功能**: 模拟真实神经形态硬件的AER总线

**总线特性**:

- 32位地址线
- Req/Ack握手协议
- FIFO事件队列
- 批量传输支持

**地址编码**:

```
Bit31: 极性 (0=OFF, 1=ON)
Bit30-16: X坐标 (0-32767)
Bit15-0: Y坐标 (0-65535)
```

### 3.5 内存级H.264编码器 (InMemoryH264Encoder)

**文件**: `h264/encoder.py`

**功能**: 在内存中直接生成H.264码流，无磁盘I/O

**核心改进**:

```python
# 旧实现 (不可接受)
temp_path = "temp_i_frame.h264"
writer = cv2.VideoWriter(temp_path, ...)
writer.release()
with open(temp_path, 'rb') as f:
    data = f.read()
os.remove(temp_path)

# 新实现 (内存级)
packet_buffer = bytearray()
codec = av.CodecContext.create('libx264', 'w')
for packet in codec.encode(av_frame):
    packet_buffer.extend(bytes(packet))
return bytes(packet_buffer)
```

## 4. 数据流与工作流程

### 4.1 发送端工作流程

```python
# 1. 初始化
detector = EventDetector(
    threshold=20.0,
    use_log_space=True,
    compare_with_previous=True,
    refractory_period=0.005  # 不应期
)
encoder = EventEncoder(width, height)
writer = EventFileWriter(output_file, width, height)

# 2. 处理每一帧
for frame in video:
    # 判断是否为关键帧
    if is_keyframe:
        # 编码关键帧（内存级H.264！）
        i_frame_data = h264_encoder.encode_i_frame(frame)
        packet = encoder.encode_keyframe(frame, i_frame_data)
    else:
        # 检测事件（含不应期）
        events = detector.detect(frame, frame_idx, current_time)
        
        # 编码事件
        packet = encoder.encode_events(events, frame, include_aer=True)
    
    # 写入文件
    writer.write_packet(packet)
```

### 4.2 接收端工作流程（不插值！向量化！）

```python
# 1. 初始化
reconstructor = EventFrameReconstructor(
    width, height,
    log_threshold=20.0 / 255.0  # 与检测端一致！
)
reader = EventFileReader(input_file, width, height)

# 2. 处理每个包
prev_frame = None
for packet in reader:
    if packet.is_keyframe:
        # 关键帧: 直接解码
        frame = reconstructor.decode_keyframe(packet.i_frame_data)
        reconstructor.reset_accumulation()
    else:
        # 事件帧: 向量化不插值重建！
        frame = reconstructor.reconstruct_frame(
            prev_frame,
            packet.dvs_events,
            mode="log_space"  # 数学一致性
        )
    
    # 显示
    display(frame)
    prev_frame = frame.copy()
```

### 4.3 端到端数据流

```
[视频帧] 
    ↓
[灰度转换] → 减少2/3数据量
    ↓
[对数空间] → log(I + 1)
    ↓
[帧差计算] → |log(I[t]) - log(I[t-1])|
    ↓
[不应期约束] → 过滤高频噪声
    ↓
[阈值比较] → 产生ON/OFF事件
    ↓
[事件编码] → DVS坐标 + AER地址
    ↓
[序列化] → 二进制数据包
    ↓
[输出] → 文件/网络/总线
    ↓
[解包] → 还原事件
    ↓
[帧重建] → 向量化，对数空间，不插值
    ↓
[显示] → 重建帧
```

## 5. 关键设计决策

### 5.1 为什么不插值？

| 考虑因素  | 不插值      | 插值       |
| ----- | -------- | -------- |
| 延迟    | ⭐⭐⭐⭐⭐ 极低 | ⭐⭐ 有延迟   |
| 计算量   | ⭐⭐⭐⭐⭐ 极小 | ⭐⭐ 较大    |
| 带宽    | ⭐⭐⭐⭐⭐ 相同 | ⭐⭐⭐⭐⭐ 相同 |
| 视觉质量  | ⭐⭐⭐ 有闪烁  | ⭐⭐⭐⭐⭐ 平滑 |
| 硬件复杂度 | ⭐⭐⭐⭐⭐ 简单 | ⭐⭐ 复杂    |
| 事件兼容性 | ⭐⭐⭐⭐⭐ 完美 | ❌ 冲突     |
| 数学一致性 | ⭐⭐⭐⭐⭐ 完美 | ❌ 破坏     |

**决策理由**:

- 事件型系统天然适合不插值（事件即变化）
- 关键帧刷新可消除累积误差
- 硬件实现更简单
- 延迟最低
- 向量化重建速度极快

### 5.2 对数空间的优势

```
线性空间: 差值 = |I1 - I2|
对数空间: 差值 = |log(I1+1) - log(I2+1)|

优势:
1. 符合人眼感知 (Weber-Fechner定律)
2. 压缩高亮度区域动态范围
3. 增强低亮度区域细节
4. 乘法变化变为加法变化
5. 检测端与重建端数学对称
```

### 5.3 关键帧策略

| 策略     | 说明         |
| ------ | ---------- |
| 固定间隔   | 每N帧发送一个关键帧 |
| 场景变化检测 | 当变化超过阈值时发送 |
| 累积误差控制 | 定期刷新防止误差累积 |

**默认配置**: 每30帧一个关键帧

### 5.4 不应期策略

| 不应期   | 效果       | 适用场景   |
| ----- | -------- | ------ |
| 0ms   | 无约束，事件最多 | 高频变化场景 |
| 1-5ms | 适度抑制     | **推荐** |
| 10ms+ | 强抑制，事件最少 | 低频变化场景 |

## 9. 总结

本系统实现了**不插值事件相机系统**的完整功能链（重构版）：

✅ **光输入** → 视频文件/摄像头\
✅ **预处理** → 灰度/对数空间\
✅ **事件检测** → DVS像素级事件（含不应期）\
✅ **事件编码** → DVS + AER格式\
✅ **打包输出** → .evs文件/网络/总线\
✅ **接收解码** → 反序列化\
✅ **帧重建** → 向量化，对数空间，不插值\
✅ **显示** → 重建帧可视化

**核心优势**: 低延迟、高压缩、简单性、AER硬件兼容、数学一致性
